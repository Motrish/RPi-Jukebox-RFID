## Required findings

1. **P1 — A foreign HTTP 200 listener can be announced as ready.** `installation/websetup/launch.py:125` checks only that the owned nginx child is currently alive, then connects to the public outer port; at line135 any `/setup/` HTTP200 is sufficient. Nginx can remain alive during bind retries after discovering an occupied port, while an already-running foreign HTTP server answers that request. The launcher can therefore print both ready URLs at lines174-175 before its own nginx ever owns the port, then fail later when nginx exits. Repeated readiness connections also touch the foreign listener: Root's supplied Linux result fails the existing collision check after its passive `listen(1)` queue is filled. Establish collision rejection and ownership before accepting HTTP readiness, and never probe/adopt an already-occupied outer listener. Add a bounded active foreign-server fixture that answers `/setup/` with HTTP200, verifies no ready URLs are published, and confirms its service remains usable and unsignaled. Keep actual-nginx coverage; do not merely weaken the existing queue assertion. Related test locations are `test/websetup/test_launch.py:159` and `:520`.

2. **P2 — A dollar sign in the private filesystem path changes the nginx document root.** `installation/websetup/launch.py:60` quotes backslashes and double quotes but permits `$`; the result is used as the template's `root` at `resources/default-settings/nginx.bootstrap-loopback.conf:33`. Nginx root paths support variable expansion, including inside quoted paths. For example, a literal TMPDIR directory component `$server_port` is a literal part of the verified extracted filesystem path but becomes the requested port number in nginx's root. Configuration validation can succeed and proxied `/setup/` can return200, while `/` and static assets resolve outside the verified webroot. Reject variable-bearing private paths before `_start_upstream` (a conservative dollar-sign rejection is sufficient), or otherwise guarantee exact literal representation. Add a real-nginx regression for such a temporary parent and require either exact verified static content or rejection before any listener. The [official root directive documentation](https://nginx.org/en/docs/http/ngx_http_core_module.html#root) confirms variable support; Root supplied that focused documentation check. No new arbitrary-root/template option is needed.

3. **P2 — The general failure handler can print private POSIX paths.** `installation/websetup/launch.py:267` uses `str(error)` for OSError/ValueError/RuntimeError and hides it only when it contains the literal word `path` or a Windows drive marker. Ordinary POSIX errors from, for example, `logs.mkdir` at line189 or private temporary-directory creation/cleanup include a quoted filename such as `/tmp/i01b-bootstrap-.../nginx-prefix/logs` without either marker. A full disk or filesystem permission failure consequently prints that path to stderr, contrary to the failure-diagnostic contract. Use fixed, actionable public messages for raw filesystem/process exceptions, preserving only deliberately authored safe diagnostics and the existing bounded BundleError messages. Add a focused exception-seam regression containing a private POSIX path and assert that no path or arbitrary exception payload reaches output.
