# I01b ownership closure report

This narrow closure is based on the reviewed source snapshot and changes only the whitelisted launcher, nginx template, and launcher test. It closes the two ownership/readiness findings and the later real-nginx matrix false positive. The shell entry and V3 workflow remain byte-identical.

The launcher now places a fresh random marker in a response header generated by the rendered, fixed nginx template. A readiness request carries only a fixed probe header and never sends the marker. The launcher accepts readiness only when it sees HTTP 204, exactly one matching marker response header, and the owned child remains alive. This distinguishes the spawned nginx from a foreign service that appears after the early bind-availability check and returns 204 while echoing request headers.

Readiness parsing is limited to HTTP status and headers. The socket has a monotonic overall deadline, the parser caps headers at 8,192 bytes and 64 fields, and it does not read response bodies. New regressions simulate a foreign 204 responder that echoes the fixed request probe and slow/oversized headers; both must fail readiness within the bounded interval.

The prior CI HTTP-matrix failure at `/setup/` was a test-classification false positive: nginx's built-in duplicate-Host 400 page is generic HTML, not the React SPA. The matrix now fetches the verified `/index.html` once and compares forbidden-route error bodies against those exact bytes. Status expectations are unchanged. A focused regression proves generic nginx error HTML is accepted by the body classifier and the actual SPA index is rejected. Matrix failure diagnostics include target, actual and accepted status, and response headers.
