## Required findings

1. **P1 — The CLI rejection test fails while creating its second fixture.** `test/websetup/test_launch.py:47` creates build/static/js with mkdir(parents=True), without exist_ok. The loop at line72 calls base_args(temporary) again at line74 for every subcase in the same TemporaryDirectory. After the first case, the directory already exists, so the second case raises FileExistsError before invoking the launcher. Build the real bundle once before the loop and reuse its immutable arguments, or give each case a separate temporary directory. This is a harness defect independent of product behavior.

2. **P1 — The browser interceptor aborts its own required setup navigation and preflight fetch.** `test/websetup/test_launch.py:230` allows only CRA document/static paths; /setup/ and /api/preflight are absent. The global interceptor at line241 therefore aborts page.goto(.../setup/) at line247, and would also reject I01a's fetch. Acceptance cannot reach either setup facts or React. Add these exact same-origin GET endpoints to the allowed request policy while retaining rejection and reporting for all other requests.

3. **P1 — The setup-page locator matches multiple elements and does not establish loaded facts.** `test/websetup/test_launch.py:250` uses get_by_text('Systemdaten', exact=False).wait_for(). Unchanged I01a index.html already contains this substring in its introductory paragraph (line16) and heading (line19); the successful fetch adds it to the state message (line54). Playwright's strict locator is ambiguous even after finding2 is fixed. Assert a unique successful loaded state and rendered fact rows, and associate the observed /api/preflight response with valid redacted facts. A static heading is insufficient evidence of the required browser fetch/render behavior.

4. **P2 — Readiness accepts an authority-rejected request.** `test/websetup/test_launch.py:163` calls raw_http without Host headers; raw_http explicitly disables automatic Host generation. At line169 any status below500, including the expected HTTP400 for missing Host, is readiness. Signal and child-exit checks can consequently act before the launcher has passed its own readiness and URL-publication point, and the happy-path check does not establish the claimed ready service. Send the exact Host authority and require the expected successful response; synchronize the ready URL assertions as well if their ordering/flushing is part of the acceptance guarantee.

5. **P2 — Lifecycle subchecks do not clean up when a regression fails an assertion or deadline.** `test/websetup/test_launch.py:292`, `:313`, and `:334` start subprocesses without a surrounding finally teardown. A readiness failure, missing-child assertion, HTTP error or communicate timeout exits the helper with its launcher and possible nginx child alive. The main integration try/finally does not own these later processes. Give every spawned fixture unconditional bounded cleanup, retaining and checking its owned descendants; preserve diagnostics without relying on the CI step/job timeout to terminate them.

6. **P2 — The uploaded report can claim PASS before failing required checks.** `test/websetup/test_launch.py:399` writes status PASS before the first launcher's clean shutdown, URL checks, input/sentinel preservation, SIGINT/SIGTERM, unexpected-child-exit and quoted-path assertions at lines409-429. A failure in any of those cases leaves a PASS report in the always-uploaded directory. Write PASS only after all assertions complete, append those checks to the report, and emit a finite failure summary if acceptance stops earlier.

7. **P2 — The invalid-bundle check does not prove verification precedes every listener.** `test/websetup/test_launch.py:78` waits for the launcher to exit and checks only the requested port afterward at line94. A launcher that briefly starts nginx or another listener before rejecting the bundle and cleaning up passes this test, violating the explicitly required pre-listener verification boundary. Add an observation of startup ordering, for example a recording failing nginx fixture plus a scoped bind/listener observation or a narrow unit seam, and assert no serving startup occurs on invalid intake. Keep the real producer and real-nginx acceptance path.

8. **P2 — The HTTP matrix omits specifically required routing rejection cases.** `test/websetup/test_launch.py:177` never sends an absolute-form request target and substitutes /unknown-api for an unknown /api/... route. It also has no negative /setup or /setup/... case. A configuration accepting absolute-form targets or routing arbitrary API/setup paths to SPA HTML could pass this matrix. Add these concrete negative requests with the correct Host and verify failure responses are not SPA HTML. Retain the existing duplicate/foreign/empty/whitespace authority, method and traversal cases.
