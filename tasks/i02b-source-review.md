## Required findings

1. P1 - Correct the mutation fake's contradictory recordings and assertions. test/websetup/test_worker.py:37-47, 336-345, 400-409. FakeHandler appends the actual config object and then mutates that same object. Consequently its recorded applied config contains audioOutput='changed' and its recorded observed config contains rfidEnabled=False. Both mutate=True tests assert these lists equal the original CONFIG and deterministically fail on Linux even when the worker copies correctly. Capture an independent input value before mutating the received object, and separately assert received copies do not alias each other or the stored target config. Keep assertions proving the worker's persistent desiredConfigSummary remains unchanged.

2. P1 - Release the active job before the second submit in the handler/store error test. test/websetup/test_worker.py:242-246. A single successful worker iteration confirms CHECK_SYSTEM and returns the first job to QUEUED; it does not complete the three-step job. The next submit therefore raises JOB_CONFLICT before reaching the intended store-error assertions. Finish the first fixture or use a separate initialized journal for the store-error case.

3. P1 - Isolate the database and lease rebinding cases. test/websetup/test_worker.py:304-333. The database case deliberately leaves a RUNNING job, then restores the DB path without terminating that job. The lease case consequently fails at the active-job check on lines307-308 and never runs. Its cleanup also unlinks the real DB and tries to restore a nonexistent jobs.sqlite3.moved, even though this case moved only the lease. Use an independent temporary journal for each case and restore only the path actually moved. Verify both cases leave persisted RUNNING intent and no observation/confirmation, and that a subsequent valid owner can recover once identities are restored.

4. P2 - Translate ordinary failures while validating the opened lease. installation/websetup/worker.py:237-250. The first os.fstat(descriptor) is outside a redacting exception handler. An ordinary OSError closes the descriptor through except BaseException but is then re-raised directly, exposing an untyped infrastructure error and potentially its raw detail. Preserve cleanup and propagation for KeyboardInterrupt/SystemExit, but convert ordinary infrastructure exceptions to WorkerError('WORKER_UNAVAILABLE') from None. Add a regression that injects this failure, checks the public error and formatted traceback, verifies the opened descriptor is closed, and verifies a later run can acquire the lease.

5. P2 - Suppress raw exception context when genuine journal errors cross the worker boundary. installation/websetup/worker.py:293-307, 317-341, 343-356; existing jobs.py:_transaction. Genuine JobError is correctly distinguished from a JobError thrown by a handler, but baseline JobStore converts SQLite exceptions with an unsuppressed exception context. Worker propagates that chain unchanged, so a genuine failing SQLite operation can put its original private text in a formatted worker traceback. Preserve the genuine JobError instance/code while suppressing its raw context at the worker boundary; no journal schema or baseline method changes are needed. Test with a genuine journal operation failure after opening the store, including formatted traceback redaction and lease release. The existing trigger fixture, once finding2 is fixed, is rejected by JobStore's exact schema check at construction and never reaches its intended failing UPDATE, so its current str-only assertion does not cover this boundary.

6. P2 - Complete the required crash and intent-order evidence using observed effects. test/websetup/test_worker.py:173-216, 417-470. The process tests create or omit an effect marker, but recovery observes a constant FakeHandler('APPLIED'/'NOT_APPLIED') unrelated to that marker. They would still report observed success/absence if the real marker state contradicted those constants. The after-effect test reads RUNNING only after the marker exists; that does not establish the required independently reopened journal read before the effect. Make the synthetic observer inspect the real temporary marker, record/count actual apply effects, and make the child handler reopen JobStore and assert persisted RUNNING/current step before creating its marker. Keep both real kill points, busy-without-mutation assertions, bounded waits and child cleanup. These assertions should fail if begin_step moves after the effect or if recovery re-applies.
